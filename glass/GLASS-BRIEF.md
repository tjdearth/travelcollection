# Glass — AI Proposal Assistant for Travel Collection

## The One-Liner

Glass is an AI associate that lives inside TCL CRM. It builds v1 proposals from agent briefs, and the advisor reviews and refines — like an MD reviewing an associate's work.

---

## The Problem

When an advisor gets a brief from an agent, the current workflow is:

1. Read the brief in Gmail
2. Mentally translate requirements into services, hotels, transfers
3. Search Salesforce for suppliers and past trips
4. Build the itinerary day-by-day
5. Price everything (except hotels — that's a separate manual process)
6. Write the email reply to the agent
7. Agent comes back with changes → repeat steps 2-6
8. Repeat 4-5 times before the trip sells

This takes 60-90 minutes per proposal version. With 4-5 versions per trip, that's 4-5+ hours of advisor time per sale — most of it mechanical assembly, not creative judgment.

## What Glass Does

Glass handles the mechanical work. The advisor focuses on judgment.

### The Workflow

```
Brief arrives in Gmail
        ↓
Advisor clicks "Glass" in TCL CRM sidebar
        ↓
Glass reads the brief, pulls agent profile from SF,
queries services/suppliers/similar past proposals
        ↓
Glass builds a complete v1 proposal with reasoning:
  - Services matched to brief interests (semantic, not just popular)
  - Hotels selected and sequenced (best hotel last, not first)
  - Transfers added automatically based on how travel works in that destination
  - Pricing rolled up (gross, including agent commission + margin)
  - Reasoning explained: "I picked X over Y because the brief says Z"
        ↓
Advisor reviews in the sidebar (1-5 min):
  "Swap this hotel — they stayed there before"
  "Add ceramics on Day 4, the mom paints"
  "Good call on the fishing, keep it"
        ↓
Glass revises, shows a focused diff (not the whole proposal again)
        ↓
Advisor approves → Glass creates trip in Salesforce
        ↓
Glass drafts reply email in the advisor's voice,
shaped for the agent's preferences → saves as Gmail draft
        ↓
Advisor reviews draft, hits send
        ↓
Agent comes back with changes → Glass handles revision (v2, v3...)
with short, delta-focused updates
```

**Before Glass:** 60-90 min per proposal version.
**With Glass:** 5-10 min per version. Advisor reviews instead of building.

## How It Works Technically

### Built on the Claude Agent SDK

Glass runs on Anthropic's managed agent infrastructure. The backend is:

- **Glass Orchestrator** — coordinates the workflow, delegates to specialists
- **Proposal Builder agent** — parses briefs, selects services, assembles itineraries, prices
- **Agent Liaison agent** — understands agent preferences, learns advisor voice, drafts emails
- **Reporter agent** — pipeline, performance, destination analytics

These run server-side. TCL CRM's frontend gets a new panel that streams Glass's responses as a chat interface.

### Salesforce MCP Server

Glass talks to Salesforce through an MCP (Model Context Protocol) server that exposes your travel platform as tools:

- `search_services` — find experiences, guides, restaurants by destination. Claude reads service descriptions to match against brief interests.
- `search_transfers` — find transfer routes and pricing
- `get_agent_profile` — pull agent booking history, patterns, and notes
- `get_similar_proposals` — find past proposals for same destination/pax to see what blocks exist
- `get_destination_patterns` — analyze delivered trips to understand how travel works in a country
- `search_suppliers`, `get_traveler_history`, `create_trip`, `update_trip`, etc.

### Gmail Integration

Glass reuses TCL CRM's existing Gmail ↔ Salesforce bridge. No separate Gmail auth needed. It reads the brief from the email on screen, drafts replies in the same thread, saves as Gmail drafts.

### Skills — Codified Institutional Knowledge

Skills are rules that make Glass's proposals feel like they were built by a senior advisor:

**Proposal Craft Rules** (apply to every trip):
- Never put the best hotel first — build anticipation
- Match tempo to the brief (relaxed = max 1 activity/day, packed = full days with variety)
- Place a wow experience near the end — strong finish
- Keep arrival day light — transfer + check-in + maybe dinner
- Avoid single-night stays — min 2 nights per property
- Don't schedule activities on departure day
- Turn travel days into experiences (stop en route)

**Destination Skills** (per country, derived from data):
- Morocco: guide + driver model. Price per day, don't add individual transfers.
- Japan: point-to-point. Every move is a discrete transfer. Meeting points matter.
- Italy: mixed. Driver for countryside, walkable in cities.
- These are generated by analyzing past delivered trips, not hand-written.

**Agent Awareness:**
- Glass pulls the agent's SF record + booking history + notes
- Shapes both the proposal content and the email reply
- Detail-oriented agents get itemized breakdowns
- High-level agents get the story and a summary

## Key Design Decisions

### Advisor as Curator, Not Builder
Glass doesn't present a menu of options for the advisor to pick from. It makes the decisions and defends them. The advisor reviews — most of the time they tweak 1-2 things. Occasionally they tear it up. But the starting point is a complete proposal with reasoning, not a blank canvas.

### Semantic Matching on Descriptions
We don't need a tagging project. Glass queries services by destination + type from Salesforce, then Claude reads the descriptions and matches against the brief's interests. A description like "Hands-on pasta making in a private home kitchen, suitable for all ages" matches "food & wine" + "family with teens" without any tags.

### Past Proposals Inform Blocks, Not Structure
Historical data tells Glass what blocks exist and work operationally. It does NOT tell Glass what to suggest — that would regress to cookie-cutter itineraries. The creative selection comes from matching the brief's specific interests. The bespoke magic is using proven LEGO blocks in a unique assembly driven by what each client actually wants.

### Hotels Are Estimated, Not Solved
There is no API for boutique hotel rates. Hotels say "check our website." Glass shortlists the right hotels from Salesforce, estimates rates from past bookings, and the advisor handles availability/rate confirmation manually. Glass makes sure that's the ONLY thing the advisor spends time on — everything else is assembled.

### 4-5 Versions Is Normal
A trip typically takes 4-5 proposals before it sells. Glass treats the trip as a living conversation with versioning. Each revision is fast — Glass shows a diff against the previous version, not the whole proposal. Email replies for revisions are short and delta-focused.

### Glass Lives Inside TCL CRM
Advisors already live in Gmail with TCL CRM. Glass is a new panel in the existing tool — not a separate app, not a new login. It reuses TCL CRM's Gmail and Salesforce connections. The advisor opens Gmail one morning and there's a new capability in the tool they already use.
